U-04 알림 · v0.4 초안 — 대화창 패러다임

핵심 패러다임 전환. v0.3 04(카테고리 우선 동적 폼)을 폐기하고 대화창(음성+텍스트) primary로 재설계. 사용자는 자연어로 의도를 말하면 AI가 알림·플랜을 조립하고 reasoning을 피드백. 단순 케이스는 한 줄 응답, 복잡 플랜은 다중 턴 조정. "전체 스케줄 보여줘" 같은 명령형 대화로 시각화도 호출. 폼은 보조 경로(편집·수동 작성)로 남김.

그레이스케일 + 라인 아이콘 시멘틱 색: 정보 파랑 v0.4 = 대화 패러다임

왜 폼 → 대화로 갔나

v0.3의 04 카테고리 우선 폼은 시니어 검토에서 풀지 못한 약점 ③ "AI 작업 조립 부담"의 미봉책이었다. 사용자가 카테고리를 고르고 폼을 채우고 AI 블록을 조립하는 모든 단계가 "쉽게 만든다"는 목표와 어긋남.

2026-05-15 세션에서 사용자가 직접 제안: 설정 화면(폼) → 대화창에서 음성으로 표현. 예: "아침 7시 날씨+일정 브리핑 보내줘" / "7월 17일 시험에 맞춰 공부 스케줄" / "전체 스케줄 보여줘".

이 방향은 메모리의 [[project_alarm_ai_assembly]](AI 조립 = 핵심 기능)와 정합되면서, 동시에 사용자에게 조립 부담을 0으로 줄이는 길. AI가 조립을 대신하고 reasoning만 보여준다.

미작성

v0.4 핵심 결정

대화창 = primary 생성 경로 — 카테고리·블록·시간 같은 추상 선택이 사라짐. 사용자는 의도를 자연어로 표현하면 AI가 모든 조립을 처리. "AI가 조립을 한다" 가 메모리에 박힌 핵심 기능 정의 [[project_alarm_ai_assembly]]의 진정한 구현.

Reasoning은 대화 흐름에 따라 다름 — 단순 알림("아침 7시 브리핑")은 reasoning 없이 한 줄. 복잡 플랜("시험 스케줄")은 reasoning 박스로 휴리스틱 명시(취약 자주·주말 모의·복습 전환). 사용자가 "왜 이렇게?" 물을 일을 선제적으로 답.

결과 = 단순 완료 + "보기" 탑 — 풀시트 미리보기 X (사용자 명시). 대화 흐름을 끊지 않고 한 줄 + 탑으로 처리. 사용자가 원하면 풀뷰로 진입(07).

"대화로 수정" = 07의 primary 액션 — 플랜 풀뷰에서 폼 편집보다 대화 수정을 우선 노출. 패러다임 일관성 — 만들 때 대화, 수정할 때도 대화.

04 폼은 보조 경로로 격하 — 폐기는 아님(편집·수동 작성 케이스). 단 진입 우선순위는 ① 대화 ② 폼(고급/엣지케이스). 신규 사용자는 폼 존재 자체를 모르고도 모든 일을 처리할 수 있어야 함.

메인 컴포저 = 대화창 진입점 (가정) — 메인 v6.10 컴포저 가정만 — 메인 화면 자체는 현재 미완. [[project_design_v6_ios_hig]] 작업 완료 후 정합 작업 필요.

미결 · 후속 라운드

  • 04 폼 retrofit — AI 조립 결과 세부 편집 경로 + AI 안 쓰고 수동 작성 경로. 화면 디자인 사용자 합의 후 작성.
  • 음성 인식 정확도·취소 — 잘못 들렸을 때의 정정 UX, 침묵 감지, 중간 발화 표시. 표준 음성 UX(Siri·Whisper) 참조.
  • 다국어 발화 — 한국어 + 영어 혼용(과목명 영어, 시간 한국어 등). AI는 처리 가능하나 UI는 별도 검토.
  • 오프라인·전송 실패 — 음성 인식·AI 호출이 안 되는 케이스. 텍스트 입력으로 fallback + 로컬 임시 저장 후 재시도.
  • 대화 히스토리 — 이전 대화 다시 보기 / 검색. 알림 센터(01) 안의 별 탭 또는 별 화면.
  • 메인 화면 컴포저 정합 — 메인 v6.10이 완성된 후 진입점 UI 정렬.
  • Paywall 인라인 — Free 한도 초과·Pro 기능 시도 시 대화 안에 인라인 paywall. [[Paywall]] 결제 v0.2와 정합.
