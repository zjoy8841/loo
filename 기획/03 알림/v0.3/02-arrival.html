정시성 모델 — 약점 2 보완

원칙: 알림의 정시성과 AI 결과를 분리한다.
알림은 항상 정각에 뜨고, AI 결과는 준비되는 대로 채운다. 결과 때문에 알림이 늦어지지 않는다.
11:50~
선실행 — 알림 10분 전부터 백그라운드에서 AI 작업 시작.
12:00 ⓐ
선실행 성공 → 정각에 결과 포함 알림 발화(폰1 첫 카드 / 폰2 배너).
12:00 ⓑ
지연 → 선실행이 정각까지 못 끝나면, 정각에 "준비 중" 상태로 일단 발화(폰1 둘째 카드). 알림 자체는 늦지 않음.
12:00+
결과 갱신 — 작업이 끝나면 같은 알림이 결과로 바뀜(in-place 갱신, Live Activity식). 새 알림으로 또 울리지 않음.
실패 시
부분 결과 + 사유 + "다시 시도/직접 보기". 위치 권한 없음 등은 설정 바로가기.

인터랙션 매핑

1
잠금화면 스택 — 도착한 알림이 잠금화면에 쌓임. 네 가지 상태가 한눈에: 결과 포함 / 준비 중(진행 바 + shimmer) / 실패(빨간 강조 + 다시 시도/부분 결과 미니 버튼) / 단순 알림.
2
준비 중 카드 — "뉴스 정리 중… 곧 도착" + 진행 바. 결과 자리는 shimmer 플레이스홀더. 완료되면 그 자리에 결과가 채워짐.
3
배너 (앱 사용 중) — 상단에 잠깐 표시 후 사라짐. 알림 본체는 01 센터에 남음. 탭 → 결과 펼침 / 관련 화면 이동.
4
진행 시트 — 준비 중 알림 탭 → AI 작업 단계별 진행(검색→요약→생성). 02 생성 폼에서 조립한 AI 작업 블록이 그대로 진행 단계가 됨.
5
작업 멈춤 — 진행 시트·롱프레스 메뉴에서 실행 중인 AI 작업을 즉시 취소(약점 5와 연결). "나중에 보기" → 준비 중 상태로 센터에 남김.
6
실패 시트 (폰4) — 단계별 진행에서 어디까지 됐고 어디서 막혔는지 노출. 완료 단계 ✓ · 실패 단계 ! · 대기 단계는 사라짐(실패 시 후속 단계는 의미 없음). 부분 결과 박스 + 사유 박스 + 액션 변경: 진행 중일 땐 "작업 멈춤/나중에 보기"였던 자리가 실패 시엔 "다시 시도/직접 보기"로 바뀜. 권한 문제(위치·알림 권한 없음)면 "다시 시도" 자리가 "설정 열기"로 추가 분기. 잠금화면 실패 카드(2b)도 같은 액션을 미니 버튼으로 노출 — 사용자가 시트까지 안 들어와도 즉시 처리 가능.

동작·상태 규칙

·
결과 카드 탭 → 06 결과 상세. 잠금화면 결과 카드(폰1 첫째)·배너(폰2)·01 센터 결과 카드 모두 같은 도착지. iOS rich notification 식 in-place 확장은 보조로 — 짧은 미리보기 더 보기까지만.
·
단순 알림(AI 작업 없음)은 선실행 과정 없이 정각에 바로 발화 — 정시성 이슈 없음.
·
선실행은 디바이스·네트워크 상황에 따라 보장되지 않음 → "준비 중" 상태가 정상 경로이지 예외가 아님. 기획·개발 모두 ⓑ를 기본 가정으로 설계.
·
방해 금지·요약 시간대에 도착한 AI 작업 알림: 선실행은 그대로, 발화만 요약 시각으로 미뤄짐(결과는 이미 준비된 상태로 전달).
·
접근성: 준비 중 상태는 aria-live="polite"로 "결과 준비 중 → 결과 도착" 전환을 발성. 진행 단계는 순서 있는 리스트. shimmer는 장식이므로 aria-hidden.
