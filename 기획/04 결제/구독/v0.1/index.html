v0.1 핵심 결정

PG는 외부 핸드오프 — 카드 raw 입력 폼은 우리 화면에 두지 않는다. 결제수단 선택까지만 우리가 그리고, 실제 인증·토큰화는 PG(토스페이·카카오페이·Stripe 등)에 위임. PCI-DSS 준수 부담 회피 + 사용자 신뢰(자체 UI에 카드번호 안 받는 게 오히려 안전해 보임).

Trial = 진입장벽 ↓ + 자동결제 명시 의무 — 7일 무료는 conversion 강화하지만, 다크패턴 비난을 피하려면 종료일·자동결제 금액을 항상 두 번 보여준다(01·02). 03 완료 화면에선 다음 결제일을 강조하고 "3일 전·1일 전 알림" 약속.

관리 허브 = 신뢰의 표면 — "어디서 해지하지?"가 안 보이는 앱이 가장 욕먹는다. 04 Hub는 현재 상태·다음 결제일·해지 진입을 모두 노출. 해지는 위험 색이지만 숨기지 않는다(EU 소비자 보호 표준).

해지 플로우의 진정성 — Retention 제안은 1단계만, 강제 N단계 보내지 않는다. "할인·일시정지·비활성 알림"은 사용자가 명시한 이유에 맞춰 1개만 제시. "그래도 해지" 항상 노출.

결제 실패는 비동기 도메인 — PG 콜백 또는 다음 갱신 주기에서 실패가 비동기로 발생. 알림 v0.3의 정시성 모델과 정합 — 실패 알림이 02 알림 도착의 실패 시트 변형으로 떠야 하며, 06 결제 실패 화면은 알림 탭의 도착지.

미결 — 시니어 검토에서 흔들 항목

  • Plan 구조 — 단일 vs 멀티(Pro/Premium). 단일이면 picker 최소화, 멀티면 비교 테이블 패턴.
  • 가격 — ₩9,900/월은 placeholder. 시장 조사·페르소나 ARPU 미반영.
  • 진입점 확장 — 마이페이지 외에 paywall(기능 잠금)·온보딩 마지막 단계가 conversion에 결정적. v0.2에서 추가 검토.
  • 인앱 vs 웹 — Apple/Google 인앱 결제 30% 수수료. 웹 결제 우회 시 앱 정책 위반 가능. 이번 v0.1은 웹 가정.
  • 환불 정책 — 7일 환불·일할 계산·전액 보장 등 정책 본문은 노션 description에 둠.
  • Plan 변경 정책 — 업그레이드는 즉시 + 일할 차액, 다운그레이드는 다음 결제일부터. 04 Hub에서 명시 필요.
  • 실패 자동 재시도 일정 — 3일 후·7일 후 등 정책. Stripe Smart Retries 차용 가능.
