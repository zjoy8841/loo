U-?? 결제(구독) · v0.2 초안

v0.1에 대한 시니어 SaaS 기획자 검토에서 나온 약점 4가지를 보완한 버전. Free 사용자 진입 화면을 신규 작성하고, paywall(기능 잠금) 화면을 추가하고, PG 외부 핸드오프 중 상태를 정의하고, 환불 정책을 명문화했습니다.

그레이스케일 + 라인 아이콘 시멘틱 색: 정보 파랑 · 위험 빨강 v0.2 = 약점 4종 보완

v0.2 수정 ① — Free 사용자 진입 화면 신규 · 2026-05-15

v0.1의 04 Hub는 구독자 전용이라 Free 사용자가 마이페이지 진입 시 갈 곳이 없었음. → 신규 00 마이페이지 구독 섹션으로 상태 분기 표면화. Free = 파란 업그레이드 카드 + Free 사용량 미터 → 01. Pro = 04 hero 압축 카드 → 04. 사용량 미터가 자연스러운 paywall 진입 동기로도 기능.

v0.2 수정 ② — Paywall 신규 (Pro-only 잠금) · 2026-05-15

SaaS conversion 핵심 경로가 v0.1에 없었음. 진입점을 "마이페이지 단일"로 제한하면 사용자가 Pro 가치를 인지할 일이 거의 없음. → 신규 07 Paywall — Pro-only 기능 시도 순간 잠금 + 시도한 작업 컨텍스트 보존(blur) + Pro 가치 3줄 + Trial 강조 → 01. 3 변형 정의(AI 작업 한도·미션 플랜·고급 모델). "Free로 계속" escape hatch 항상 노출(다크패턴 회피).

v0.2 수정 ③ — PG 외부 핸드오프 중간 상태 정의 · 2026-05-15

v0.1은 02 CTA → "PG 외부" → 03을 가정만 두고 그 사이를 비워뒀음. webview 로드 중·콜백 대기·사용자 백키 등 실제 케이스 미정의. → 02 결제 확인 phone 2로 진행 중 오버레이 추가 — scrim + 토스페이 로고 + 펄스 dots + "취소하고 돌아가기" escape. 성공/실패/타임아웃/백키 4 케이스 동작 caption에 박음.

v0.2 수정 ④ — 환불 정책 확정 · 2026-05-15

v0.1은 05 caption에 "노션 description에서 정의"라고 미뤘는데, 결제 도메인에서 환불 정책은 와이어프레임에 박혀야 화면이 그려짐. → 정책 1개 확정: "남은 기간 사용 후 자동 종료, 환불 없음"(월·연 동일). 05 폰2에 환불 정책 박스 추가 — Trial 케이스(₩0)와 정식 구독 케이스 두 분기 모두 명시. 법정 변심 환불(7일)은 03 success 직후만 적용되는 별 정책으로 분리.

시니어 검토 약점 → v0.2 보완

v0.1을 시니어 SaaS 기획자 시점에서 비판적으로 검토해 도출한 약점 7가지 중, 사용자가 v0.2에서 다룰 4가지를 확정. 나머지 3가지(Trial→정식 전환·다운그레이드 UX·안심 시그널)는 후속 라운드.

v0.2 핵심 결정 (누적)

진입은 4 갈래 — ① 마이페이지(Free 카드/Pro 카드) ② Paywall(Pro-only 시도) ③ Pro 관리(04 Hub) ④ 비동기(결제 실패 알림). v0.1의 단일 진입에서 conversion 핵심 경로 추가.

Paywall = "지금 이 작업을 하려면" 패턴 — 추상적 "Pro 사세요"가 아니라 사용자가 방금 시도한 작업을 컨텍스트로 보존(blur) + 결제 후 그 작업으로 자동 복귀. 결제만 하고 끝나면 paywall 효력 절반.

PG 핸드오프 = 우리 화면의 일부 — webview 띄우고 끝이 아니라, 우리 화면 위 scrim + escape hatch + 4 케이스 동작이 정의되어야. 사용자가 "결제 됐나 안 됐나" 모르는 순간이 절대 없게.

환불 = 단순한 한 줄 — "남은 기간 사용 후 종료, 환불 없음". 일할 환불 없음이 운영 단순화 + 사용자에게도 "체험 중 해지하면 안전, 정식 후엔 만료까지 사용" 이라는 명확한 멘탈 모델. Stripe·Spotify·Netflix 표준.

(v0.1 유지) PG 외부 핸드오프 / Trial = 진입장벽 ↓ + 자동결제 명시 / 관리 허브 = 신뢰의 표면 / 해지 retention 1단계만 / 결제 실패 = 알림 정합.
