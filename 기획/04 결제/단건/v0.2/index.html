U-?? 단건 결제 · v0.2 초안

v0.1에 대한 시니어 SaaS 기획자 검토에서 나온 약점 12가지 중 가장 critical한 4가지를 보완한 버전. 결제 실패 화면을 신규 작성하고, 식당 측 수락 모델을 도입해 03을 phone 3개 상태 분기로 확장하고, 예약 상세 관리 hub를 신설하고, 사용자 출발지 컨텍스트를 명시했습니다. 나머지 8 약점은 v0.3 후속.

그레이스케일 (와이어프레임) 강조는 굵기·보더·outline로 v0.2 = 약점 4종 보완

v0.2 수정 ① — 결제 실패 화면 신규 · 2026-05-18

v0.1은 02 caption에 "결제 실패 = v0.2 라운드"로 미뤘는데, 결제 실패율 5~15%는 화면이 필수. → 신규 04 결제 실패. 단건 고유 4 사유 분기 — 잔액 부족·한도 초과·PG 일반 오류·슬롯 마감·식당 영업 종료. 사용자 행동이 다르므로 phone 2개(결제수단 문제 / 컨텍스트 문제)로 분리. 슬롯 임시 홀드(15분) 박스 명시 — 사용자가 재시도 시 같은 자리 보장.

v0.2 수정 ② — 식당 측 수락 모델 + 03 phone 3개 확장 · 2026-05-18

v0.1의 즉시 자동 수락 가정은 거짓이었음 — 식당이 점심 피크에 5~10분 내 수락/거절. 03이 "예약 확정됐어요" 단언 시 거절 시 신뢰 붕괴. → 02 결제 확인에 "식당 수락 안내" 박스 추가 + 03를 phone 3개로 분기: ⑴ 수락 대기(결제 직후) ⑵ 예약 확정 ⑶ 예약 거절·환불. 진입 시 phone 1, 1~2분 내 phone 2 또는 phone 3 자동 전환. 라이언이 거절 시 대안 메뉴 즉시 제안.

v0.2 수정 ③ — 예약 상세 hub 신규 · 2026-05-18

v0.1은 03에서 "예약 상세에서 취소" 링크 제공했지만 도착지가 없었음. 결제 후 사용자 관리 진입점 부재. → 신규 05 예약 상세. 구독 04 hub와 같은 위상 — 상태 hero + 영수증 + 지도 stub + 4 액션(길찾기·식당 연락·일정 변경·취소) + 현재 시각 환산 환불 정책 + 라이언 안내 + 활동 타임라인. 5 상태(대기·확정·완료·거절·취소) 분기는 caption에 매핑. 03 phone 1·2 CTA / 5분 전 푸시 / 마이페이지 / 알림 센터 모두 여기로 도착.

v0.2 수정 ④ — 출발지 컨텍스트 바 · 2026-05-18

v0.1 라이언 박스가 "회사에서 도보 5분"을 단언 — 외근·재택·주말 시 거짓. → 01 메뉴 상세 헤더 아래 출발지 컨텍스트 바("회사 · 강남구 테헤란로 · 변경") 신규. 탭 = 직장/집/현 위치(GPS)/직접 입력 4 옵션. 라이언 박스 본문이 "현 출발지에서 도보 5분"으로 자동 갱신. GPS 거부 시 직장 fallback. 출발지 시트 자체는 사용자 설정 hub와 묶어 v0.3.

시니어 검토 약점 → v0.2 보완

v0.1을 시니어 SaaS 기획자 시점에서 비판적으로 검토해 도출한 약점 12가지 중, v0.2에서 4가지(CRITICAL·HIGH)를 다룸. 나머지 8가지(MED·LOW)는 v0.3 후속.

v0.2 핵심 결정 (누적)

"확정"이라는 단어는 식당 수락 후에만 — v0.1은 결제 = 확정으로 단언했음. v0.2는 결제 → 수락 대기 → 확정의 3단 상태 분리. 02 안내 박스에서 미리 인지 → 03 phone 3개에서 상태 시각화. 결과적으로 사용자가 "확정"이라는 단어를 봤을 때 그게 진짜 확정임을 보장.

실패는 사유별로 다른 화면이 되어야 — "결제 실패"라는 단일 화면은 다크패턴. 사용자 행동이 결제수단 문제(수단 바꾸기)와 컨텍스트 문제(메뉴·시간 바꾸기)에서 완전히 다름. Phone 2개로 분리 = 사용자가 다음 행동에 헤맬 시간 X.

관리 hub는 단건 결제의 두 번째 정체성 — 첫 정체성 = 라이언 추천. 두 번째 = 사용자가 예약을 들여다보고 행동하는 곳. 05 hub는 결제 후 모든 알림·외부 진입의 도착지. 활동 타임라인으로 사용자가 "지금 어디까지 진행됐는지" 한눈에 — 고객지원 비용도 ↓.

라이언이 거절·실패 시점에도 일관되게 작동 — v0.1 라이언은 추천·확정 양 끝의 따뜻함만 담당. v0.2는 거절(03 phone 3)·실패(04 phone 2)에서도 대안 메뉴 제안으로 후속 행동을 제시. 사용자가 막힌 곳에서 빠져나오는 책임을 라이언이 짐.

출발지는 "회사" 단언 X — 사용자가 명시 — v0.1 라이언이 "회사에서 5분"을 단언하는 순간 외근·재택·주말 시 거짓. v0.2는 헤더 바에 출발지를 박아 사용자 인지 → 라이언 신뢰 보장.

(v0.1 유지) 라이언 추천 컨텍스트 정체성 / "확정"이 아닌 "예약" 표현 / 환불 시간 기반 3단계 / 구독과 결제수단·PG 공유 / 5분 전 알림 도메인 약속.
