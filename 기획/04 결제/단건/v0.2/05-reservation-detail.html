위상 — 단건 결제의 hub CRITICAL

★
구독 04 hub와 같은 위상의 사용자 관리 진입점. 결제 후 사용자가 예약을 들여다보고 행동하는 모든 경로의 도착지.
  • 03 phone 1 "예약 상세로" → 여기 (수락 대기 상태)
  • 03 phone 2 "예약 상세에서 취소" → 여기 (확정 상태)
  • 5분 전 푸시 알림 탭 → 여기 (확정 + 5분 전)
  • 마이페이지 "내 예약" → 여기 (현재 활성 예약)
  • 알림 센터 [[project_alarm_user_process]] = 최근 결과 도착지

① 헤더 — 뒤로 + 상태 pill

1
← 뒤로(이전 화면 복귀). 우측 pill은 현재 상태(확정/대기/완료/거절/취소). 확정 = 검정 채움, 대기 = 흰 보더, 거절·취소 = 점선 보더 — 모두 그레이스케일 안에서 강도 분리.

② 상태 hero — 검정 배너 CRITICAL

2
검정 배경 배너로 핵심 상태 + 핵심 정보 + 다음 약속 3줄. "오늘 12:30 · B카페"가 사용자에게 가장 중요한 정보 — hero에서 먼저 인지. 다음 약속(5분 전 알림)을 명시해 사용자가 다음에 무엇을 기대해야 하는지 알게 함.

상태별 변형:
  • 수락 대기 — 시계 아이콘 + "B카페가 수락하면 알려드릴게요" + "보통 1~2분"
  • 확정(현재 화면) — ✓ + "오늘 12:30 · B카페" + "5분 전 알림 약속"
  • 완료 — ✓ + "12:30 · B카페에서 식사 완료" + "또 가기 / 다른 메뉴" 안내
  • 거절 — X + "B카페가 예약을 잡지 못했어요" + 환불 정보
  • 취소 — X + "사용자가 취소" + 환불 정보

③ 예약 정보 — 8 필드 영수증

3
03 phone 2 영수증 + 식당 혼잡도 pill(여유/보통/혼잡). 사용자가 가기 전에 한 번 더 확인. 출발지 컨텍스트(약점 ④) 반영 — "도보 5분"이 출발지 기반.

④ 지도 stub CRITICAL

4
식당 위치 + 도보 경로 미니 지도. in-app vs 외부 지도 앱 분기 미결(약점 ⑫). v0.2는 stub만 박고 v0.3에서 결정.
  • 옵션 A — in-app 미니 지도 (Naver Maps API): 일관성 ↑, 비용 ↑
  • 옵션 B — 정적 이미지 + "지도 앱에서 열기": 비용 ↓, 외부 의존

⑤ 예약 관리 — 4 액션 CRITICAL

5
2×2 그리드:
  • 길찾기 — 외부 지도 앱 인텐트 (식당 좌표)
  • 식당 연락 — 전화 인텐트 (예약 정보 제공 약관에 따라 식당 전화번호 표시)
  • 일정 변경 — 시간 변경 시트 (같은 식당의 다른 슬롯). 30분 전까지만 가능(cutoff)
  • 예약 취소 — 환불 정책에 따라 환불 + 취소. 검정 보더로 위험 신호
상태별 활성/비활성:
  • 수락 대기 — 취소만 가능 (수락 안 됐으므로 변경 의미 없음)
  • 확정 — 4 액션 모두 가능, 단 시간 변경·취소는 cutoff 적용
  • 완료 — 길찾기·식당 연락 X / 일정 변경 X / "또 가기"·"리뷰" 등 v0.3 변형
  • 거절·취소 — 모두 X (액션 그리드 숨김), "대안 보기" CTA만

⑥ 환불 정책 — 시간 기반 + 현재 시각 환산 CRITICAL

6
02 환불 정책 박스의 cutoff(30분/5분)를 구체 시각으로 환산("지금 ~ 12:00 전액"). 사용자가 "30분 전이 언제더라" 계산 X. 현재 시각이 cutoff에 가까워지면 박스 강조 (예: 12:00 5분 전부터 "곧 부분 환불로 전환" 안내). 박스 자체는 환불 가능한 활성 예약에만 표시(완료·거절·취소 후 미표시).

⑦ 라이언 — 컨텍스트 안내

7
현 상태에 맞는 라이언 안내. 확정 상태 = "12:25 알림" 약속. 다른 상태별 분기:
  • 수락 대기 — "수락 진행 상황" 약속
  • 완료 — "오늘 점심 어땠어요? 기록할까요?" — 데이터 쌓기 유도
  • 거절·취소 — 대안 제안(02 식당 수락 안내·03 phone 3 톤)

⑧ 활동 타임라인 CRITICAL

8
예약의 전 생애 주기를 사용자가 한눈에. 결제 → 수락 → 5분 전 알림(예정) → 매장 도착(예정) — 검정 점 = 완료, 점선 점 = 예정. 시각·짧은 텍스트·부가 정보 3줄.
  • 사용자가 "지금 어디까지 진행됐는지" 즉시 인지
  • 고객지원 문의 시 사용자가 시각 기반으로 설명 가능
  • 거절·취소 시 해당 이벤트 추가, 이후 점 제거

⑨ CTA — 주 액션 1개

9
하단 고정 = 현재 상태의 가장 자연스러운 다음 행동 1개. 확정 = "길찾기 시작". 수락 대기 = (없음, 닫기만). 완료 = "또 가기"(같은 메뉴 빠른 결제). 거절·취소 = "대안 메뉴 보기"(01로). 4 액션 그리드와 중복되지만, 하단 fixed CTA는 thumb zone 우선.

미결: "또 가기" 빠른 결제는 [[project_solo]] 시연 시 강력한 conversion. 약점 ⑧ 재방문 진입점과 묶어 v0.3.
