① 헤더 · 2/3 단계

1
← / "결제 확인" / 2/3. ← 탭 = 01 메뉴 상세로 복귀(시간 슬롯 선택 유지). 사용자가 결제 직전에 메뉴를 다시 검토할 수 있는 명확한 경로.

② 메뉴+시간 요약 — 변경 가능 CRITICAL

2
01에서 선택한 메뉴·식당·시간·거리를 readonly로 표시. "변경" 링크 = 01 복귀. 결제 직전 재확인 — "내가 뭘 결제하는지" 한 박스에 다 보임. 시간이 화면에 박혀 있어야 환불 정책 박스가 직관적으로 읽힘(③ 박스와 호응).

③ 환불 정책 — 시간 기반 3단계 CRITICAL

3
예약 시간 기준 30분 전 / 5분 전 / 노쇼 3단계. 위 ②에 예약 시간이 박혀 있어 "내 케이스가 어디 해당하는지" 즉시 계산 가능. 마지막 줄 = 식당 측 거절 시 전액 환불(사용자 보호 신호). 빨강 박스 — 시멘틱 색 = 위험·주의.

미결: 30분/5분 cutoff는 식당과 협의 후 확정. 일부 메뉴(조리 시작 후 환불 불가)는 별 정책 필요할 수 있음. v0.2 라운드.

④ 결제수단 — 구독 v0.2 02와 동일 CRITICAL

4
토스·카카오·네이버·삼성 + 카드 fallback. 구독 도메인과 동일 SDK·동일 결제수단 row 사용 — 사용자가 두 결제 도메인을 같은 결제 표면으로 인지(학습 비용 ↓). 토스페이 default.

⑤ 약관 동의 — 식당 정보제공 추가

5
필수 2 + 선택 1.
  • 결제·환불 약관(필수) — ③ 환불 박스 본문 포함
  • 식당에 예약 정보 제공(필수) — 구독에 없는 단건 전용. 이름·메뉴·시간·인원 식당에 전달. 전화번호는 기본 미전달(노쇼 위험 시 식당 요청으로만)
  • 이 식당의 다음 추천 받기(선택) — 사용자의 식당 선호 데이터로 사용
"전체 동의" 없음 — 다크패턴 회피, 구독 v0.2와 같은 정책.

⑥ 합계 — 단건 가격

6
메뉴 + 예약 수수료(무료) + 지금 결제 금액. 01에서 보여준 합계와 정확히 일치. 예약 수수료를 줄로 박는 이유 = 사용자가 "예약 = 부가 비용 없음"을 한 번 더 확인.

⑦ CTA → PG 외부 CRITICAL

7
"₩8,500 결제하기" — 금액을 CTA에 박음(사용자가 무엇을 결제하는지 마지막 확인). 필수 약관 미동의 시 disabled. 탭 = 선택 PG SDK 외부 진입.

⑧ PG 진행 중 오버레이 (phone 2) CRITICAL

8
구독 v0.2 02-checkout의 오버레이 패턴 그대로 재사용 — scrim + 중앙 카드(토스 로고 + 펄스 dots + "취소하고 돌아가기" + 안전 안내).

해결 상태별 동작:
· PG 성공 콜백 → 03 예약 확정으로 이동
· PG 실패 콜백 → 오버레이 해제 + 02에서 토스트 "결제 실패: [사유]" + 사용자 재시도. 예약 슬롯은 해제 X(15분 임시 홀드)
· webview 백 키 → 02 그대로 복귀
· 30초 timeout → "확인 중..." 안내 추가 + 60초 후 강제 해제

미결: 단건 결제 실패 화면(v0.2 06 패턴 단건 변형) 필요 — 카드 잔액 부족·예약 슬롯 마감 같은 단건 고유 사유 분기. v0.2 라운드.
