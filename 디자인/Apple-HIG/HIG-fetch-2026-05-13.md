## 0. 요약 — v7.1 §6에 영향 큰 발견 (TL;DR)

| v7.1 §6 항목 | HIG 실제 | 액션 제안 |
|---|---|---|
| WCAG AA 대비 표 — **14pt+bold 경계** | Apple은 **17pt 경계** 사용 (`Up to 17pt`=4.5:1 / `18pt`=3:1 / `Bold`=3:1). 14pt+bold는 W3C WCAG 1.4.3 정의지 Apple 정의 아님. | v7.1 §4 접근성 표의 "14pt+bold" 표현 → **17pt 경계 + Bold any-size = 3:1**로 교체 또는 두 기준 병기 |
| Dynamic Type **11개** 텍스트 스타일 정확한 pt 값 | iOS Large(default) 11스타일 모두 확보 ✓. v7.1 §1의 매핑(Display=Large Title 34pt, H1=Title 1 28pt 등) **정확함** | v7.1 §1 그대로 두고 §6 체크박스만 해소. clamp() 최소/최대값은 xSmall(31pt)~xxxLarge(40pt) 범위로 재검토 가능 |
| 시스템 Material **5단계** 정확한 블러 강도 | Apple HIG는 standard material을 **4단계만 명시** (`ultraThin · thin · regular · thick`). Liquid Glass는 별도 functional 레이어. **블러 px/pt 수치는 미공개** — 의미론 이름만 사용. | v7.1 본문 "5단계 블러 강도"가 §5에 있다면 **4단계 + Liquid Glass 별도 레이어** 구조로 교정. 블러 수치는 절대값 대신 "system material 의미론 이름 사용" 가이드로 전환 |
| safe-area-inset 동작 검증 (iPhone 14 Pro) | iPhone 14 Pro = **393×852pt @3x = 1179×2556 px** 확인 ✓. 단 safe-area-inset의 **고정 pt 수치는 HIG 미공개** — 디바이스/오리엔테이션별 동적, `safeAreaInsets` API / CSS `env(safe-area-inset-*)`로 처리. | v7.1 §6 체크 → "고정값 대신 API/env() 사용" 가이드로 전환 |

**추가 발견 (v7.1 본문 보강 후보):**

- **(중요)** Apple 공식 가이드: **"Avoid hard-coding system color values. Documented color values are for your reference during the app design process. The actual color values may fluctuate from release to release."** → v7.1이 hex로 컬러 토큰을 못 박는 방향이면 이 caveat을 §3 컬러 토큰 표 위에 명시 권장.
- **터치 타깃**: iOS 기본 44×44pt / 최소 28×28pt (`Accessibility` 페이지). v7.1 §4 보강 후보.
- **Increased Contrast 모드**: 시스템 컬러 토큰은 **4 모드 변형** 보유 — `Default(light) · Default(dark) · Increased contrast(light) · Increased contrast(dark)`. v7.1 §3 컬러 토큰을 이 4-mode 구조로 정렬하면 HIG와 1:1 매핑.
- **iOS 배경 컬러 계층**: `system` + `grouped` × `primary/secondary/tertiary` = 6 background tokens. v7.1 §2 시점별 surface 룰과 맞춰 검토 가능.

## 2. Accessibility — WCAG 대비 + 터치 타깃 (출처: `/accessibility`)

### 2-1. WCAG AA 대비 (Apple 공식 기준) **★ §6 항목 1**

| Text size | Text weight | Minimum contrast ratio |
|---|---|---|
| **Up to 17 pt** | All | **4.5 : 1** |
| **18 pt** | All | **3 : 1** |
| **All sizes** | **Bold** | **3 : 1** |

> 출처 문장: *"Accessibility Inspector uses the following values from WCAG Level AA as guidance in determining whether your app's colors have an acceptable contrast."*
> Apple은 W3C WCAG 1.4.3의 "18pt OR 14pt+bold = large text" 정의가 아닌 **17pt 경계 + Bold any-size = 3:1** 룰을 사용.

### 2-2. 터치 타깃 (Default & Minimum Control Size)

| Platform | Default | Minimum |
|---|---|---|
| iOS, iPadOS | **44×44 pt** | 28×28 pt |
| macOS | 28×28 pt | 20×20 pt |
| tvOS | 66×66 pt | 56×56 pt |
| visionOS | 60×60 pt | 28×28 pt |
| watchOS | 44×44 pt | 28×28 pt |

### 2-3. 기타 가이드

- *"If your app doesn't provide this minimum contrast by default, ensure it at least provides a higher contrast color scheme when the system setting **Increase Contrast** is turned on."*
- *"If your app supports Dark Mode, make sure to check the minimum contrast in both light and dark appearances."*
- 2개 표준 언급: WCAG + **APCA (Accessible Perceptual Contrast Algorithm)**.

## 3. Materials — 시스템 material & vibrancy (출처: `/materials`)

### 3-1. 표준 material 단계 **★ §6 항목 3 — 단계 수 교정 필요**

iOS/iPadOS는 콘텐츠 레이어에서 **4단계만** 명시:

| Material | Recommended for |
|---|---|
| `ultraThin` | Full-screen views that require a light color scheme |
| `thin` | Overlay views that partially obscure onscreen content and require a light color scheme |
| `regular` | Overlay views that partially obscure onscreen content |
| `thick` | Overlay views that partially obscure onscreen content and require a dark color scheme |

별도 **Liquid Glass** functional 레이어 (controls/navigation용, 2025-06-09 도입):
- 두 variant: `regular`(텍스트 영역용, 대부분 시스템 컴포넌트) / `clear`(미디어 배경 위 floating용)
- "content layer에는 사용 금지" — 명시적 가이드

visionOS: 시스템 정의 `glass` material(수정 불가) + `thin/regular/thick` 3단계 의미.

### 3-2. Blur 강도 수치 — **미공개**

Apple HIG는 4단계 material의 **블러 반경(pt/px) 수치를 공개하지 않음**. 의미론 이름만 사용하고 시스템이 컨텍스트에 따라 강도를 결정. → v7.1에 절대값 박는 대신 "system material 이름 사용 + 자체 토큰 정의 시 OS 시뮬레이터 캡처 비교" 방식 권장.

### 3-3. Vibrancy 정량 레벨 (참고)

- **Labels** (4단계): `label (default) · secondaryLabel · tertiaryLabel · quaternaryLabel`
  - 단 `quaternary`는 `thin`/`ultraThin` 위에선 대비 부족으로 비권장
- **Fills** (3단계): `fill (default) · secondaryFill · tertiaryFill`
- **Separator** (1단계): system default

## 4. Layout — safe area & 디바이스 스펙 (출처: `/layout`)

### 4-1. safe-area 처리 원칙 **★ §6 항목 4 — 접근 방식 교정**

Apple HIG 본문(요약):
- *"A safe area defines the area within a view that isn't covered by a toolbar, tab bar, or other views a window might provide. Safe areas are essential for avoiding a device's interactive and display features, like **Dynamic Island** on iPhone or the camera housing on some Mac models."*
- **고정 pt 수치 테이블 없음** — 디바이스/오리엔테이션별 동적, 시스템이 `safeAreaInsets`로 제공.
- iOS 가이드: *"Avoid full-width buttons. Buttons feel at home in iOS when they respect system-defined margins and are inset from the edges of the screen."*

→ v7.1 권고: 픽셀 검증 대신 **`safe-area-inset-*` env() 변수 / `safeAreaInsets` API 사용 의무화** + 시뮬레이터에서 Dynamic Island/홈 인디케이터 가림 여부 시각 검증.

### 4-2. iPhone 14 Pro 스펙 (v7.1 §6에서 명시 참조)

| Model | Dimensions (portrait) |
|---|---|
| **iPhone 14 Pro** | **393×852 pt** (1179×2556 px @3x) |
| iPhone 14 Pro Max | 430×932 pt (1290×2796 px @3x) |
| iPhone 16 Pro | 402×874 pt (1206×2622 px @3x) |
| iPhone 16 Pro Max | 440×956 pt (1320×2868 px @3x) |
| iPhone Air | 420×912 pt (1260×2736 px @3x) |

> 전체 디바이스 표는 `layout-scan.json` (idx 8, 49 rows).

### 4-3. iOS, iPadOS Size Classes

iPhone 14 Pro: Portrait = `Compact width · Regular height` / Landscape = `Compact width · Compact height`.
iPad 전 모델: 모든 오리엔테이션에서 `Regular width · Regular height`.

→ v7.1 §1/§2/§6에 "Compact width(iPhone 세로)" 기준으로 기본 디자인하고 iPad에서 layout 재배치 가이드 필요 여부 검토.

## 5. Color — 시스템 컬러 토큰 구조 (출처: `/color`)

### 5-1. ★★ 핵심 caveat (반드시 인지)

> *"**Avoid hard-coding system color values in your app.** Documented color values are for your reference during the app design process. **The actual color values may fluctuate from release to release**, based on a variety of environmental variables. Use APIs like Color to apply system colors."*

→ v7.1이 컬러 토큰을 hex 고정값으로 박는다면 **상단에 이 caveat 박스 + "참고용, 실제 구현은 시스템 API 호출"** 표기 권장.

### 5-2. 시스템 컬러 토큰 스키마 **★ 4 모드 구조**

모든 시스템 컬러는 4개 모드 변형 보유:

| Default (light) | Default (dark) | Increased contrast (light) | Increased contrast (dark) |
|---|---|---|---|

→ v7.1 §3 컬러 토큰 표를 이 4-column 구조로 재정렬하면 HIG와 1:1.

### 5-3. SwiftUI 표준 컬러 12종

`red · orange · yellow · green · mint · teal · cyan · blue · indigo · purple · pink · brown`

### 5-4. iOS UIKit 시맨틱 라벨/구분선 8종

`label · secondaryLabel · tertiaryLabel · quaternaryLabel · placeholderText · separator · opaqueSeparator · link`

### 5-5. iOS 시스템 그레이 6단계

`systemGray · systemGray2 · systemGray3 · systemGray4 · systemGray5 · systemGray6`

### 5-6. iOS 배경 컬러 계층

iOS는 **두 set × 3 단계 = 6 background tokens**:

- **System set** (일반): `systemBackground · secondarySystemBackground · tertiarySystemBackground`
- **Grouped set** (grouped table view용): `systemGroupedBackground · secondarySystemGroupedBackground · tertiarySystemGroupedBackground`

계층 룰: Primary = 전체 view / Secondary = view 안 그룹 / Tertiary = secondary 안 그룹.

→ v7.1 §2의 시점별 surface 룰(라이트/다크 자동 토글)을 이 2×3 구조와 정렬하면 시스템 룩 자동 추종.
